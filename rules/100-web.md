## DESIGN TOKENS — only semantic tokens, never raw values

NEVER write: hardcoded hex (`#3B82F6`) · raw color class (`text-gray-500`) · arbitrary value (`p-[13px]`)
ALWAYS write: CSS var (`--color-primary`) · semantic class (`text-muted-foreground`) · grid value (`p-3`)

```css
/* Required token structure (read DESIGN-SPEC.md if present) */
--color-primary        --color-primary-hover   --color-surface
--color-surface-raised --color-muted           --color-border
--radius-sm --radius-md --radius-lg
--shadow-sm --shadow-md --shadow-lg
--transition-fast(100ms) --transition-base(200ms) --transition-slow(300ms)
```

## DESIGN CONTINUITY — before any UI addition/edit

Read 1-2 existing components/pages of the same type first; extract color usage, type scale, spacing, component structure. Match existing tokens exactly — new elements must resolve to the `--color-*` set already in use (check warm/cool balance + contrast against neighboring elements, not just isolated contrast ratio). Never introduce an off-palette accent without checking `DESIGN-SPEC.md` (if present) first.

Within one project: every section/page stays visually unified — same tokens, type scale, spacing, and component patterns end-to-end. Do not vary layout or hierarchy between sections of the same site for variety's sake; cohesion beats novelty inside a single project.

Across projects: never default to the previous project's layout/template. Each new project establishes its own original, premium-feeling design character (layout, hierarchy, detail) — reusing the last project's design wholesale is the anti-pattern, not a shortcut.

## 8PX GRID — only these spacing values

Valid px: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128
Tailwind: p-1(4) p-2(8) p-3(12) p-4(16) p-6(24) p-8(32) p-12(48) p-16(64)
NEVER: p-5 · p-7 · p-9 · p-[13px] · gap-[18px] · mt-[17px]

## TYPOGRAPHY

Two font families max: display (headings) + body (reading). Never one font for both.
Type scale ratio: 1.333 (Perfect Fourth). Max 4 sizes visible simultaneously.
Line height: body=1.6 · headings=1.1-1.2
Letter spacing: headings=-0.02em · body=0

## TAILWIND V4 DETECTION

Signal: `@import "tailwindcss"` in CSS + no `tailwind.config.js` file
v4 mode: `@theme` directive replaces config | CSS variables are the theme system
Container queries built-in: `@container` + `@sm:` / `@lg:` variants
`:has()` via `has-*:` variant

CSS layer order: `@layer reset, theme, base, components, utilities`
Container queries → for components | Media queries → for layouts

## THREE MANDATORY STATES — every data-driven component

Loading: skeleton matching content shape (NEVER spinner for list/card/table)
Empty: icon + headline + description + CTA button (all 4 required)
Error: message + recovery action (retry button or alternative)

### Skeleton shapes by content type

| Content | Shape |
| --- | --- |
| Text paragraph | 3 lines — widths 100% / 80% / 60% |
| Card | aspect-ratio box + 2 text lines below |
| Table row | cells matching column widths exactly |
| Avatar + name | circle + single line |
| Image | same aspect-ratio box as final image |
| List item | icon circle + 2 text lines |
| Stat / number | single wide rect |

Shimmer animation left→right, max 1.5s duration. Match final layout exactly.

### Empty state formula (4 elements, all required)

```json
[Icon — large, muted, matches content type]
[Headline — "No {things} yet" — direct, never "No data available"]
[Description — 1 sentence: what the user can do]
[CTA button — "Create your first {thing}" — specific, actionable]
```

Empty state tiers: first-use=instructional | no-results=recovery ("Try different keywords") |
error=reassuring+retry | permissions=explain+upgrade

## MOTION RULES

Enter: `opacity 0→1` + `translateY 8-16px → 0` · max 300ms · `cubic-bezier(0.2, 0, 0, 1)`
Exit: `opacity 1→0` only · max 150ms (exit faster than enter)
Staggered list: 50ms delay per item · max 8 items staggered, then batch
Page transitions: View Transitions API (native, zero KB) preferred over Framer Motion
Complex sequences only: Framer Motion | GSAP only when platform insufficient

ALWAYS wrap: `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; } }`

Micro-interactions:

- Button press: `scale(0.97)` 100ms
- Card hover: `scale(1.02)` + shadow-sm→shadow-lg 200ms
- Focus ring: 2px solid `--color-primary`, offset 2px, `cubic-bezier(0.2, 0, 0, 1)` 150ms

## ACCESSIBILITY — WCAG 2.2

| Rule | Requirement |
| --- | --- |
| Semantic HTML | `<button>` not `<div onClick>` · `<nav>` not `<div className="nav">` · `<main>` · `<article>` |
| ARIA labels | Every icon-only button must have `aria-label` |
| Form labels | Every input needs visible `<label>` (not just placeholder) |
| Focus ring | NEVER `outline: none` without explicit replacement |
| Focus not obscured (2.4.11) | Sticky headers must not fully cover focused element |
| Target size (2.5.8) | Interactive targets ≥ 24×24px (44×44px recommended) |
| Color contrast | Body text: min 4.5:1 · Large text: min 3:1 · Never convey info by color alone |
| Keyboard nav | All interactive elements reachable by Tab · no keyboard traps |
| Screen reader | Async content updates → `aria-live="polite"` or `role="status"` |
| Modal | `role="dialog"` + `aria-modal="true"` + focus trap + Escape closes |
| Drag (2.5.7) | Every drag action must have single-pointer alternative |

`A11Y: [element] — [issue]` → fix immediately, do not just flag.

## DARK MODE

Next.js: `next-themes` (SSR-safe, cookie-based). Add `suppressHydrationWarning` on `<html>`.
NEVER: `localStorage` alone for SSR projects (causes hydration flash).
Pattern: `<html class="dark">` set server-side from cookie.
CSS: `@media (prefers-color-scheme: dark)` only for no-toggle-needed cases.

## SEO (Web projects — Next.js 15 patterns)

### Core Web Vitals budget

| Metric | Budget | Trigger |
| --- | --- | --- |
| LCP | <2.5s | Any above-fold content change |
| CLS | <0.1 | Any layout change |
| INP | <200ms | Any interaction handler change |
| JS bundle (gzip) | <200KB initial | Any dep addition |
| Per-route extra | <100KB | New page/route |

If change likely violates budget: `PERF: [metric] — [estimated impact]`

### CLS prevention (mandatory)

Every `<img>` must have `width` + `height` attributes OR `aspect-ratio` CSS. No exceptions.
Video: `aspect-ratio` container. Font: `font-display: swap` or `optional`.

### Next.js 15 metadata

```typescript
// app/layout.tsx — global (static)
export const metadata: Metadata = {
  title: { template: '%s | SiteName', default: 'SiteName' },
  description: '...',
  openGraph: { type: 'website', images: [{ url: '/og.png', width: 1200, height: 630 }] },
  twitter: { card: 'summary_large_image' },
  metadataBase: new URL('https://example.com'),
}

// app/[page]/page.tsx — dynamic (use generateMetadata)
export async function generateMetadata({ params }): Promise<Metadata> {
  return { title: 'Page Title', alternates: { canonical: '/page' } }
}
```

File conventions (Next.js 15): `opengraph-image.tsx` per route segment · `sitemap.ts` · `robots.ts`

### JSON-LD structured data

```html
<script type="application/ld+json">{JSON.stringify({
  "@context": "https://schema.org",
  "@type": "Organization", // or Product, Article, FAQ, BreadcrumbList
  ...
})}</script>
```

Types by page: org/company=Organization · product=Product+Review · blog=Article+BreadcrumbList · support=FAQ

### SEO checklist (every new page/route)

- [ ] `generateMetadata()` with unique title + description
- [ ] OpenGraph image (1200×630)
- [ ] JSON-LD script (correct type for content)
- [ ] Canonical URL (`alternates.canonical`)
- [ ] All `<img>` have `width` + `height` or `aspect-ratio` (CLS)
- [ ] Exactly one `<h1>` per page
- [ ] All images have `alt` attribute (empty string for decorative)
- [ ] Semantic HTML: `<main>` · `<article>` · `<nav>` · `<section>`
- [ ] Link text descriptive (never "click here")
- [ ] AEO: H1 + first paragraph directly answers the query

## UNIVERSAL UI ANTI-PATTERNS — never generate

- Hardcoded hex in JSX/TSX/Vue/Svelte (`color="#333"`, `backgroundColor: "#3B82F6"`)
- Arbitrary Tailwind values (`text-[17px]` `p-[13px]` `gap-[18px]`)
- Raw color classes as semantic values (`text-gray-500` instead of `text-muted-foreground`)
- `outline: none` or `outline: 0` without visible focus ring replacement
- Spinner for data list/card/table loading (use skeleton)
- Nav chrome re-created inside page component (use layout)
- Missing loading | empty | error state (all 3 required alongside the full state)
- `alert()` or `Toast` (use project's toast/snackbar system)
- Hardcoded font size in px
- Single font when display+body pairing is required by archetype
- `<div onClick>` for actions (use `<button type="button">`)
- Static OG metadata in root layout only (every route needs its own)
