## THE RULE UNDER ALL THE OTHERS

A localized string is **not** a sentence you translate word by word. It is a message with
parameters, a plural category, and a locale-specific rendering. Every failure below comes from
treating it as text that happens to be in another language.

Never concatenate a sentence from fragments. `t('deleted') + ' ' + count + ' ' + t('items')` is
untranslatable: word order, agreement and plural rules all differ, and the translator sees three
strings with no context.

## KEYS AND CATALOGS

- Key by **meaning and location**, not by the English text: `cart.empty.title`, not
  `"Your cart is empty"`. A source-text key changes every time the copy is edited, silently
  orphaning every translation.
- One namespace per feature (`cart.*`, `auth.*`), mirroring the project's own module boundaries
  (`rules/001-conventions.md`) — not one flat file that every feature edits and every merge
  conflicts on.
- The default-locale catalog is the source of truth and lives in the repo. Never hand-edit a
  generated catalog.
- **Missing key**: throw or log loudly in development, fall back to the default locale in
  production, and never render the raw key to a user. `cart.empty.title` on screen is a bug
  report from your customer.

## PLURALS AND GENDER — ICU MessageFormat, never a ternary

English has two plural forms, Turkish has one, Arabic has six, Polish has four with rules that
depend on the last two digits. A `count === 1 ? 'item' : 'items'` in the code hardcodes English
grammar into every language you will ever ship.

```text
WRONG:  `${count} ${count === 1 ? t('item') : t('items')}`
RIGHT:  t('cart.items', { count })
        cart.items = "{count, plural, =0 {Sepet boş} one {# ürün} other {# ürün}}"
```

Same for gender and any other branch that varies by language: `{gender, select, ...}` inside the
message, never an `if` in the component.

## DATES, NUMBERS, CURRENCY — the platform already knows

Never format by hand, never assume a separator, never assume day-month order.

```javascript
// WRONG: 3.14 renders as "3.14" in a locale that writes "3,14"; MM/DD is wrong outside the US
`${d.getMonth() + 1}/${d.getDate()}/${d.getFullYear()}`

// RIGHT
new Intl.DateTimeFormat(locale, { dateStyle: 'medium' }).format(d)
new Intl.NumberFormat(locale, { style: 'currency', currency: 'TRY' }).format(amount)
new Intl.RelativeTimeFormat(locale, { numeric: 'auto' }).format(-3, 'day')
new Intl.ListFormat(locale, { type: 'conjunction' }).format(names)
```

- **Currency is data, not a locale property.** The user's locale decides how `1234.5` is written;
  the price decides that it is TRY. Never infer one from the other.
- **Money is never a float.** Minor units as integers, or a decimal type — a rendering rule cannot
  fix a value that was already rounded wrong.
- **Store UTC, render local.** A timestamp without a timezone is a defect that surfaces at a
  DST boundary months later.
- **Sorting is locale-specific**: `Intl.Collator(locale).compare` — a plain `.sort()` puts Turkish
  `ı`, German `ä` and Swedish `ö` in the wrong place.
- **Turkish dotted/dotless i**: `toLowerCase()`/`toUpperCase()` without a locale corrupts `I`/`İ`.
  Use `toLocaleLowerCase(locale)`, and never case-fold a value you intend to compare for identity
  (emails, usernames) with a locale-sensitive function.

## RTL — a direction, not a stylesheet

- Use **logical properties** throughout: `margin-inline-start`, `padding-inline`, `inset-inline-end`,
  `text-align: start`. Tailwind's `ms-*`/`me-*`/`ps-*`/`pe-*` are the same thing.
  `margin-left` in a component is what makes an RTL build a rewrite instead of a config change.
- Set `dir` on `<html>` from the locale, not on individual components.
- Mirror directional icons (back/forward arrows, progress, chevrons); never mirror logos, media
  controls (play always points at the timeline direction of playback), or numerals.
- Test with one real RTL locale in CI, not with a transform on the LTR one.

## LAYOUT — text is not a fixed length

German and Turkish run 30-40% longer than English; Japanese runs shorter and wraps differently.

- Never fix the width of a button, tab or label to its English content, and never truncate a
  translated string to make a row fit — the design has to absorb the length.
- No text inside images or icon sprites. It cannot be translated and it cannot be read by a screen
  reader (`rules/100-web.md`).
- Pseudo-localization (`[!!! Ćàŕţ íş éḿṕţý !!!]`) in a dev build finds hardcoded strings and
  overflow before a translator ever sees the product.

## ROUTING, SEO AND ACCESSIBILITY

- `<html lang="{locale}" dir="{dir}">` — screen readers switch voice on it, and it is what
  `rules/100-web.md`'s SEO section assumes is correct.
- One canonical URL per locale plus reciprocal `hreflang` on every alternate, including
  `x-default`. A single canonical shared by all locales de-indexes every non-default one.
- Locale in the path (`/tr/urunler`) or on a subdomain — never only in a cookie: a shared or
  crawled link has to open in the language it was shared in.
- Translate the slug when the content is translated, and keep a permanent redirect from the old
  one.

## ANTI-PATTERNS — never ship

```text
✗ A user-facing string literal in a component
✗ Sentence assembled from concatenated fragments or interpolated sub-strings
✗ `count === 1 ? …` instead of an ICU plural
✗ Hand-rolled date/number/currency formatting
✗ `margin-left` / `text-align: left` in a product that will ever ship RTL
✗ `toLowerCase()` with no locale on Turkish text — or with one on an email
✗ A raw key rendered to the user when a translation is missing
✗ Locale kept only in a cookie, with one URL for every language
✗ Text baked into an image
✗ A translated string truncated to fit a layout built for English
```
