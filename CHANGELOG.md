## [Unreleased]

Post-2.0.0-cut audit fixes (2.0.0 is not yet tagged/published — these land on top of it). The first two items retroactively document commit `f05268f`, whose own substance never reached the changelog.

### Removed

- **The entire `protected-paths` hook** (`hooks/protected-paths.mjs`, `hooks/lib/{patterns,bash-extract,snapshot}.mjs`, `hooks/hooks.json`, `hooks/README.md`, `scripts/hooks.test.ts`) — 13 independent audit rounds found a new bypass or blind spot in this hook nearly every time (verb enumeration gaps, PowerShell aliases, encoding obfuscation, and — most recently — a `SKIP_DIRS`/`MAX_DEPTH` blind spot in the round-12 snapshot-diff rewrite, still paired with overstated "guaranteed" language in its own comments). Rather than continue an open-ended whack-a-mole against Bash syntax, removed the hook entirely and kept only what was already deterministic without it: `settings-template.json`'s Read-tool deny rules (unchanged, still block Read-tool access to the full protected-files list) and its existing Bash-read-verb deny rules for the highest-value secret patterns (`.env`/`*.pem`/`*.key`/`id_rsa*`/`id_ed25519*`/service-account JSON via `cat`/`head`/`tail`/`type`/`Get-Content`/`gc`/`base64`). What this drops versus the hook: Bash *writes* into any protected path (auth/payment/DB-migration/CI/secrets/lockfile), Bash reads via verbs outside that fixed list, and Bash access to protected files absent from the deny list (`secrets/`, `config/credentials.json`, `*.p12`, `.ssh/`, `.secrets.baseline*`, lockfiles) — none of that is gated anymore; it's prompt discipline only (`global-CLAUDE.md` HARD STOPS + guard-agent routing). Updated every doc that described the hook as a harness-enforced guardrail (`global-CLAUDE.md`, `rules/000-security.md`, `SECURITY.md`, `SETUP.md`, `README.md`/`README.tr.md`, `TROUBLESHOOTING.md`, `UPGRADE.md`, `skills/kit-doctor/SKILL.md`) so none of them overclaim protection that no longer exists.

### Added

- `scripts/validate-skills.ts` — a 9th independent audit round found `rules/*.md` was the one artifact type with zero frontmatter validation: skills, agents, commands, and presets all had a validator checking their frontmatter shape, but a rule shipped with `path:` (singular typo), an empty `paths:` block, or a missing `paths:` key would silently never lazy-load and still pass `npm run check` — the entire lazy-load mechanism hinges on that field. New "Validating rules/ frontmatter" pass: `000-security`/`001-conventions` must NOT have `paths:` (documented always-loaded), every other rule must have a non-empty `paths:` glob list, `path:` typos are caught explicitly. Added `getFrontmatterList()` to `scripts/lib/frontmatter.ts` since the existing flat frontmatter parser deliberately skips YAML list values.
- `scripts/validate-skills.ts` — reverse-orphan skill detection: a skill referenced by no agent's `skills:` list, not mentioned in `ROUTING.md`/`global-CLAUDE.md`/any `commands/*.md`, and not marked `disable-model-invocation: true` now fails validation. This exact "orphan skill" class was found by hand in at least two prior audit rounds before there was a permanent check for it (verified clean against the real `skills/` — 0 orphans found).
- `scripts/validate-skills.ts` — guard-agent `permissionMode: plan` enforcement switched from a hardcoded 3-agent set (`security-guard`/`db-guard`/`devops-guard`) to a name-pattern check (any `agents/*-guard.md`) — the hardcoded set silently missed `performance-guard`, which is read-only by convention (`ROUTING.md`) and already shipped `permissionMode: plan`, but wasn't validated, so a future edit could have flipped it to `default` unnoticed. `AGENTS-MAINTENANCE.md`'s quarterly checklist updated to match.
- `skills/project-memory` — a competitive scan of external "Claude Code ecosystem" repos (claude-mem, pro-workflow) found real, actively-maintained cross-session-memory tools, but both depend on lifecycle hooks plus a background worker/SQLite/vector-DB/MCP stack — exactly the mechanism class this kit removed for being unmaintainable (see the `protected-paths` removal above). `global-CLAUDE.md`'s existing CONTEXT DISCIPLINE bullet already told Claude to "persist durable facts to memory/*.md + MEMORY.md before `/clear`" but shipped no skill implementing it for consumer projects — a real, if narrower, gap. New skill teaches the lightweight version of the same idea using only Read/Write/Edit: a `.claude/PROJECT-MEMORY.md` with dated Decisions/Gotchas/Conventions/Open-questions sections, no hooks, no new runtime dependencies. `global-CLAUDE.md`'s CONTEXT DISCIPLINE bullet now points to it.
- `skills/incident-response` — a gap surfaced against `wshobson/agents`' named multi-agent orchestrators (e.g. `incident-response`, `full-stack`): the kit's guard agents and `agents/ROUTING.md` handle routing a single request to the right specialist, but nothing coordinates a live production incident across multiple guards at once with one timeline. New skill triages severity/blast-radius, dispatches to the same Step 3 guards in `ROUTING.md` in parallel, and keeps a single incident timeline for the postmortem — guard agents stay read-only planners even under incident urgency, per the kit's existing plan-then-approve model. `agents/ROUTING.md` gained a short note routing live-incident language ("prod is down", "P1", "outage") here before normal Step 2/3 dispatch.
- `.claude-plugin/marketplace.json` — added `displayName` and `category` fields to the plugin entry, matching the convention Anthropic's own first-party `knowledge-work-plugins` marketplace uses; the kit's entry previously had only `name`/`source`/`description`.
- `scripts/check-consistency.ts` — an independent review of the always-loaded-file line budget (added earlier this round) noted it caps `global-CLAUDE.md`/`rules/000-security.md`/`rules/001-conventions.md` at 250 lines *each*, so three files at 249 lines apiece would pass every check while costing 747 lines every session — the per-file cap can't see the actual combined tax by construction. Added a second, combined 500-line cap alongside the existing per-file one (current total: 422). Test-first: a fixture where every file sits under 250 individually but the sum exceeds 500 exercises the new check without tripping the old one.
- `scripts/check-consistency.ts` — a 14th independent audit round found `.claude/settings.json` (the kit's own dev config) had drifted 35 deny rules behind `settings-template.json`, missing every `base64`/`Get-Content` secret-read rule — the kit's own sessions ran with weaker protection than what it ships to consumers. `allow` is expected to diverge per project (documented in `UPGRADE.md`), but `deny` never should. Added a superset check (every template deny rule must also be present locally) so this can't silently drift again.
- `eval/golden-prompts.json` + `scripts/routing-eval.ts` — `agents/ROUTING.md` has a live-tested golden-prompt eval (`RUN_ROUTING_EVAL=1`), but the kit's 25 *skills* — matched by Anthropic's platform algorithm against each `SKILL.md`'s `description`/`when_to_use`, not by anything this repo ships — had zero behavioral coverage beyond "is the skill reachable." An architecture review scoped the smallest defensible fix: skill auto-invocation isn't this repo's algorithm to live-test (that would test Anthropic's matcher at API cost, not the kit), but the description text IS something the kit owns and can drift. Added an optional `expectedSkill` field to golden prompts plus a free static lint: fails only when a prompt and its expected skill's description/`when_to_use` share literally zero significant (4+ char, stopword-filtered) words — a deliberately weak signal that catches total drift without false-failing on paraphrase. Populated on the 8 prompts with an unambiguous, single skill match (avoided guard-area prompts where the "right" skill is a judgment call, to keep the ground truth honest). `significantWords()` unit-tested for stopword filtering, the 4-char floor, and Turkish-character preservation.

## [1.0.0] — 2026-07-02

Initial public release.

### Agents (17)

Routed agent roster covering implementation, review, and hard-stop guards: `architect`, `bug-hunter`, `db-guard`, `devops-guard`, `docs-writer`, `migration-guard`, `performance-guard`, `researcher`, `reviewer`, `security-guard`, `security-scanner`, `senior-engineer`, `strategist`, `test-engineer`, `ui-fixer`, `writer`, `academic-writer`. Guard agents (`security-guard`, `db-guard`, `migration-guard`, `devops-guard`) run with `permissionMode: plan` — they produce a written plan and pause for explicit approval before any implementation, enforced by CI (a guard agent missing `permissionMode: plan` fails `npm run validate`). `agents/ROUTING.md` documents the full decision tree: hard-stop check → stack-trace signal → guarded-domain signal → task-type signal → ambiguity resolution, plus a conflict-resolution table for when two signals match.

### Skills (34)

Auto-invoked, description-matched playbooks across application work, data/API design, quality/security, DevOps/environment, content/research, and orchestration. Hand-off chains between design-phase and deployment-phase skills (`db-change` → `migration-review`, `data-modeling` → `db-change`, `api-design` → `api-versioning`) are checked by `npm run validate`, which flags a hand-off pointing at a renamed or removed skill. Every skill body stays ≤20 non-blank lines by the same check; longer detail lives in `agent_docs/` and is lazy-loaded on demand.

### Rules (11)

Path-scoped engineering standards auto-loaded by glob match: `000-security` (always active, OWASP 2025 passive scan), `001-conventions`, `100-web`, `200-api`, `300-testing`, `400-mobile`, `500-database`, `600-devops`, `700-observability`, `800-llm-safety`, `900-performance`. `600-devops` pins IaC scanner recommendations (Checkov, Trivy) to specific released versions rather than `latest`, matching the SHA-pinning discipline the rule requires of GitHub Actions.

### Commands (13) and Presets (49)

13 rich slash commands (`/smart-task`, `/plan-first`, `/safe-review`, `/security-scan`, `/release-gate`, `/dep-check`, `/performance-check`, `/seo-check`, `/deep-research`, `/strategy-plan`, `/article-write`, `/agents-guide`, `/kit-doctor`) plus all 34 skills invocable by name. 49 stack-specific presets (98 files: `CLAUDE.md` + `compact.md` each) across web, backend, ORM, database, mobile, API, runtime, infrastructure, messaging, AI, and generic categories — see `PRESET-MAINTENANCE.md` for the version-support matrix and deprecation lifecycle.

### Enforcement layer

- `hooks/protected-paths.mjs` — deterministic `PreToolUse` hook: any Edit/Write/NotebookEdit into secrets, auth, payment, DB migration, or CI/IaC paths is downgraded to an explicit permission prompt naming the guard agent responsible, regardless of what the model decided. Fails open on unrecognized input. An `SDK_ALLOW_PROTECTED=1` escape hatch skips the prompt for an approved session and logs a structured `hook.protected_path.bypassed` audit line to stderr, so a skipped prompt stays visible instead of disappearing silently. Opt-in — installers copy it but never wire it into `settings.json` automatically; the Claude Code plugin registers it automatically.
- `settings.json` / `settings-template.json` — a Read/Bash deny list covering secret-file reads, destructive deletes, disk-destroying commands, git history rewrites, download-pipe-execute patterns, and permission-bypass installs. Cost is measured, not guessed: `npm run deny-cost` replays your own transcript history against the list (see `SECURITY.md` for the documented false-positive trade-offs, e.g. `rm -rf /*` denying all absolute-path deletes under Git Bash on Windows).

### Distribution

- `install.sh` / `install.ps1` — idempotent installers with collision-safe timestamped backups, post-copy file-count verification, and `--detect`/`-Detect` stack auto-detection across 17 framework/language signals.
- `bin/cli.mjs` — `npx senior-dev-kit [--detect | --preset=<name>]` wrapper, no clone required (Node 22.6+).
- `.claude-plugin/` — Claude Code plugin + marketplace manifest; `/plugin marketplace add` + `/plugin install` registers commands, agents, skills, and the protected-path hook automatically.
- `PROJECT-BOOTSTRAP.md` (new-project autonomous setup) and `SETUP.md` (existing-project setup, Claude-driven) as alternatives to running the shell installers directly.

### CI and verification

- `.github/workflows/repo-ci.yml` — markdown lint, YAML lint, typecheck, eslint, skill/agent/preset frontmatter validation, shellcheck, PSScriptAnalyzer, install end-to-end tests across ubuntu/macOS/windows, internal link check, staleness check, and a meta job that resolves every pinned GitHub Actions SHA against the upstream API. All Actions across all workflows are pinned to full commit SHAs, including in the workflows that check the pins.
- `eval/golden-prompts.json` + `scripts/routing-eval.ts` — 33 realistic TR+EN routing prompts pinned to the agent that should handle them. The static half (agents exist, every agent covered, no duplicates) runs on every push; the live half asks the model to actually route each prompt via the `claude` CLI and fails below a 90% pass threshold. Measured, not assumed: the first live run scored 28/33 (85%) and exposed real gaps in `ROUTING.md`; after closing them, two consecutive live runs scored 32/33 (97%).
- 119 unit/integration tests (`scripts/*.test.ts`) covering skill/agent/command frontmatter validation, hand-off chain integrity, install script behavior on both platforms, and hook behavior (protected-path matching, case-insensitive filesystem handling, audit logging on bypass).
